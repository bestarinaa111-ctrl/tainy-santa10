# Тайный Санта

Русскоязычный сайт для игры «Тайный Санта»: участники записываются по общей ссылке, организатор меняет бюджет до жеребьёвки, затем каждый получает только свой результат по личной ссылке.

## Возможности

- Русский интерфейс, праздничный адаптивный дизайн и анимированная заставка.
- Создание игры и отдельная секретная ссылка организатора.
- Присоединение по общей ссылке: участник вводит имя без регистрации.
- Проверка повторяющихся имён.
- Организатор видит список участников, но не видит пары жеребьёвки.
- Название, бюджет и валюта редактируются до жеребьёвки.
- Криптографически случайная жеребьёвка: никто не получает самого себя, каждый получает ровно одного человека.
- Личные ссылки участников; получатель раскрывается только при предъявлении личного токена.
- После жеребьёвки запись и настройки блокируются.
- В базе хранятся только хеши секретных токенов, а не сами токены.

## Локальный запуск на Windows

Нужен Node.js версии 18 или новее. Для локального режима дополнительные пакеты не обязательны.

1. Запустите `start.bat`.
2. Откройте `http://localhost:3000`.

Без переменной `DATABASE_URL` данные сохраняются в `data/secret-santa.json` на вашем компьютере.

## Публикация в интернете: Render + Neon

Эта версия умеет хранить игры в PostgreSQL. Это важно для бесплатного хостинга: локальная файловая система бесплатного Render временная, поэтому база данных вынесена отдельно.

### 1. Создайте базу данных Neon

1. Откройте https://neon.com/ и создайте проект PostgreSQL.
2. В панели проекта нажмите **Connect**.
3. Выберите основную ветку, базу данных и роль.
4. Скопируйте строку подключения (лучше вариант с `-pooler` в имени хоста). В ней должен быть параметр `sslmode=require`.
5. Сохраните строку как пароль: никому её не отправляйте и не добавляйте в файлы проекта или GitHub.

Neon предоставляет бесплатный тариф с ограничениями по объёму базы и времени работы вычислителя. После простоя база может «засыпать», но сохранённые записи остаются. Проверьте актуальные условия на странице тарифов Neon.

### 2. Загрузите проект в приватный GitHub-репозиторий

1. Откройте https://github.com/ и создайте новый репозиторий с названием `tainy-santa`.
2. Обязательно выберите **Private**.
3. Распакуйте архив проекта на компьютере.
4. Загрузите содержимое папки проекта в репозиторий (кнопка **Add file → Upload files**) и нажмите **Commit changes**.
5. Не загружайте папку `data`, `.env` или файлы с паролями/ключами. Файл `.gitignore` уже исключает `data/` и `.env`.

### 3. Создайте веб-сервис Render

1. Откройте https://render.com/ и войдите в аккаунт.
2. Нажмите **New → Web Service** и подключите GitHub.
3. Выберите ваш приватный репозиторий `tainy-santa`.
4. Укажите настройки:
   - **Runtime / Language:** Node
   - **Build Command:** `npm install`
   - **Start Command:** `npm start`
   - **Instance Type:** Free (для небольшого тестового проекта)
5. В настройках сервиса откройте **Environment** и добавьте переменную:
   - **Key:** `DATABASE_URL`
   - **Value:** строка подключения из Neon
6. Сохраните переменную и запустите деплой. Render выдаст адрес вида `https://название-сервиса.onrender.com`.

Не публикуйте значение `DATABASE_URL` и не присылайте его в чаты. Оно даёт доступ к базе данных.

### 4. Важные ограничения бесплатного размещения

- Бесплатный веб-сервис Render засыпает после периода бездействия; первое открытие после сна может занять около минуты.
- Бесплатный Render не сохраняет изменения в локальных файлах между перезапусками. Поэтому при публикации обязательно задайте `DATABASE_URL`, чтобы игры сохранялись в Neon.
- Бесплатная база Neon также приостанавливает вычисления после простоя; записи в ней сохраняются.
- Это небольшое приложение рассчитано на один экземпляр сервера. Не увеличивайте число экземпляров без перехода на полноценную общую базу/схему синхронизации.
- Сделайте резервную копию данных базы перед серьёзными обновлениями.

## Как провести игру

1. На главной странице организатор создаёт игру и задаёт бюджет.
2. Сайт показывает общую ссылку-приглашение и секретную ссылку организатора. Секретную ссылку нужно сохранить.
3. Организатор отправляет друзьям только ссылку-приглашение.
4. Каждый участник открывает приглашение, вводит имя и получает личную ссылку. Её нужно сохранить.
5. Организатор открывает секретную ссылку, проверяет список, при необходимости меняет бюджет и запускает жеребьёвку.
6. Каждый участник открывает личную ссылку и видит только имя своего получателя.

## Важные замечания по безопасности

- Не отправляйте участникам ссылку организатора.
- Не пересылайте личную ссылку участника другим людям: это его ключ доступа к результату.
- Если участник потеряет личную ссылку, восстановить её без регистрации и дополнительных данных нельзя.
- Организатор не видит распределение через интерфейс сайта. Владелец базы/сервера с административным доступом технически может получить доступ к данным сервера.
- Не публикуйте файл локальной базы `data/secret-santa.json` и никогда не добавляйте в GitHub секретные ключи или строку `DATABASE_URL`.
- Для реального публичного использования нужен HTTPS (Render выдаёт его автоматически для `onrender.com`).

## Ограничения первой версии

- Повторяющиеся имена в одной игре запрещены. При совпадении имени добавьте фамилию или отличительное слово.
- В одной игре может быть до 100 участников.
- В этой версии нет исключений для отдельных пар и повторной жеребьёвки.
- Редактировать список участников после запуска жеребьёвки нельзя.
